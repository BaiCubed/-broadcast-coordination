# Reproduction matrix

This matrix is the execution contract for the release. The artifact-level source of truth is [`code/audit/OUTPUT_REPRODUCTION_MANIFEST.csv`](code/audit/OUTPUT_REPRODUCTION_MANIFEST.csv), with one row for every file found under the reference `outputs/` tree.

## Ordered stages

| Stage | Command | Inputs | Main outputs | Verification gate |
|---|---|---|---|---|
| Layout and protocol | `./code/scripts/run_reproduction.sh --check` | Release files and protocol JSON | Syntax report and refreshed artifact manifest | 14 scenario CSVs, 105 pairwise CSVs, required configs, and Python compilation pass |
| Raw-data preprocessing | `./code/scripts/run_reproduction.sh --data` | Official source directories listed in `data/configuration/preprocessing_config.json` | Canonical 288-step caches and deterministic train/validation/test fleets | Cache metadata and generator manifest pass |
| E1-E4 | `./code/scripts/run_reproduction.sh --e1-e4` | Canonical caches and protocol YAML | E1-E4 raw tables, summaries and figures | Runner manifests and expected table schemas pass |
| E20-E24 | `./code/scripts/run_reproduction.sh --experiments` | E1-E4 outputs, raw/canonical data, models and network configs | E20-E24 seed tables, summaries, models, figures and manifests | Each experiment manifest reports completion and expected row counts |
| Final artifacts | `./code/scripts/run_reproduction.sh --artifacts` | E20-E24 result tables and source figures | Publication figures, composite panels, Appendix, supplementary tables, presentations and reports | Artifact manifest and byte/file checks pass |
| Final audit | `python code/tools/verify_outputs.py ...` | Generated `code/outputs` and artifact manifest | `code/audit/output_verification.json` | No generated artifact is missing; manual metadata assets are separately identified |

## Experiment entry points

- E1-E4: `src/extra/nc_excel_experiments/run.py` after `tools/prepare_dataset_configs.py`.
- E20: `run_e20_transfer.py`, `run_e20_fig3a_transfer.py`, and `run_e20_rotations.py`.
- E21: mixed scenarios, pairwise curtailment and R², universal and mixed Gamma boundaries, and baseline supplements.
- E22: `run_e22_ieee69_complexity.py`, trained direct models and constraint replays.
- E23: IEEE-69 pressure/failure boundary and spatial heterogeneity runners.
- E24: IEEE-123 direct training, audit, and optional OpenDSS validation.

The final-artifact builders are in `code/tools/`: `generate_boxplot_outputs.py`, `replot_results_e20_e24.py`, `generate_e22_subpanel_figures.py`, `build_e22_subpanel_presentation.py`, `build_appendix.py`, `build_supplementary_tables_s1_s4_s5.py`, `build_mixing_methods_report.py`, and `build_e23_e24_outputs.py`.

## Verification status in this draft

The short verification command is:

```bash
cd code
python scripts/verify_release.py
```

It has passed locally. It validates release layout, English documentation, source compilation, 14 mixed-scenario CSVs, 105 pairwise CSVs, deterministic summary-table checksums and regenerated summary figures. The independent composition self-test also passed against the local canonical caches for `S1-A` and `P001` in both sampling modes.

A full E1-E4/E20-E24 run was intentionally not executed because it is a multi-hour, multi-gigabyte computation. The manifest and staged runner make that chain explicit. The current verification claim is therefore release-level reproducibility and artifact-contract coverage, not a new numerical rerun of every network seed.

The release intentionally excludes raw third-party archives, trained checkpoints and intermediate result tables. They are acquired or regenerated by the documented chain. The only checked-in numeric inputs are the derived scenario and pairwise CSV summaries used for immediate release-level checks.
